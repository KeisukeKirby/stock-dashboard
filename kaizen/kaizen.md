# 経理
> 提案の軸：手入力と照合を減らす「効率化」で、毎日の確認など「品質」に使う時間を作る

### まとめ
- **59.4 時間 / 月（2 名合計）** を減らせる見込みです（NEE 31.4h・NUT 28.0h）。
- 今は 2 名で月 193.6h（NEE 104.8h / NUT 88.8h）かけています。
- 空いた約 52.5 時間 / 月は、毎日の照合・毎月の元帳・棚卸し・月次レポートへ

:::info 数字の出し方
作業時間：NUT・NEE の Daily Report（2/11〜4/3）から、決算書関連の業務を除いた時間で算出 ／ 削減見込み：Daily Report を AI が分析して出した推定 ／ 1 か月 = 21 営業日（今月の営業日数）で換算
:::

### なぜ、やり方を変えるのか
:::flow
- 今: 手入力作業や照合作業が多い
- その結果: 確認の漏れ・返金処理の遅れ・月次財務レポートの遅れ
- 変えること: AI を活用して、やり方を変える
- 効果: 効率化 → 作業時間を削減
- 空いた時間の使い道: 毎日の確認業務・返金などの迅速な処理・期限内のレポート提出
- 目的: 問題の発生を防ぐ
:::

## 売上の毎日照合と返金メモ
:::proposal
問題: 確認は毎週月曜だけ。ずれに気づくのが遅く、E-Tax は最大約 1 週間待ち
今後: 毎朝、前日の店舗・イベントの売上を照合
確認: ずれに翌営業日に気づく・E-Tax は 1〜2 営業日・返金は Refund Log へ
:::

**いつ**：毎朝（11 月 4 日から）

### 手順
1. POS と端末・QR 入金を比べて記録
2. QR とカードの誤入力・他店の混入を確認
3. E-Tax は 1〜2 営業日で発行
4. その日のうちに店舗へ確認
5. 返金・振替はすぐメモ → 金曜の支払いへ

### ① 銀行：明細を取り込み、AI の候補で照合
:::kv
時間（2 名・1 か月）: 22.4h → 9.8h（−12.6h、−56%）
区分: 品質・正確さ・入力
AI 移行の難易度: 低（入金入力・PEAK 修正＝低、銀行照合＝低）
:::

**今のやり方**

- 銀行明細を見て、入金額を手で入力
- 店舗の入金も別に入力
- 2〜3 か月分をまとめて Excel で照合
- 合わない金額を PEAK で修正

**新しい手順**

1. **毎週月曜の午前**：前週分の明細を口座ごとにダウンロード（KBank は PDF、BBL は CSV）
2. **続けて**：PEAK の銀行ファイル取込に入れ、AI 照合を選ぶ
3. **続けて**：AI の一致候補を見て、正しいものをまとめて確定
4. **続けて**：合わない分だけ原因を調べる（店舗入金は POS の売上で確認）
5. **月末**：照合レポートで残高が明細と合うか確認（作る人と確かめる人は別）

:::tip
2〜3 か月分をまとめる処理がなくなり、決算の照合も減ります
:::

# 在庫・倉庫・QC
> 在庫は Zort で管理、QC は基準どおり

## 在庫は Zort で管理
:::proposal
問題: 正確な在庫が分からず、イベント前に毎回すべて数えていた
今後: 入出庫はすべて Zort に記録。準備はシステムの在庫から出す
:::

- 在庫を動かす仕事（オンライン配送・イベント準備・返品交換・店舗補充）は倉庫担当が責任を持つ
- オフィス在庫は棚卸しして Zort に反映済み。店舗の分も順に反映
- 例：コーディネーターは梱包・配送までを請け負う

## 毎月末に棚卸し
:::proposal
今後: 経理と倉庫担当で実数を数え、システムとの差を確認
:::

**いつ**：毎月末

- 差は Stock Discrepancy Log に入力
- 棚卸しの日は補充しない。NUT が店舗へ前もって知らせる
- 必要なら棚卸しの前に補充しておく

## 伝票はセットで保管、入荷品は店頭へ
:::proposal
問題: 書類がばらばらで確認できず、入荷した商品が倉庫に眠っていた
今後: 納品書と返却伝票は 1 セットにして経理で保管
:::

- 送った数・戻った数・システムの入出庫が合うか確認
- 入荷したら、店頭へ出したかを確認
- 売れない商品は、まず店頭の在庫を確認

## 基準時間で計画する
:::proposal
問題: 基準がなく、検品待ちが何か月も残り、クレーム期限も過ぎた
今後: 足数 × 基準時間 で人数と日程を決める
確認: 開始と終了の時刻を QC シートに記録。基準と大きく違えば理由を書く
:::

### 基準時間
| 作業 | 基準 |
|---|---|
| 初期 QC | 1:40 分 / 足 |
| 接着修理 | 1:00 分 / 足 |
| 縫製修理 | — 外部委託 |
| アームスリーブ・バフ QC | 2:13 分 / 個 |
| イベント梱包（約 32.5 秒 / 足） | 111 足 / 時間 |

**例：300 足のイベント**

- 初期 QC（1 人）8 時間 20 分 ／（2 人）4 時間 10 分
- 梱包（1 人）2 時間 40 分 ／（2 人）1 時間 20 分

## 初期 QC：全足を 4 つに分ける
:::proposal
問題: 人によって判断がちがった
今後: 検査項目は同じ。1 足 1 分 40 秒
確認: 戻ってきた不良の数（月ごと）
:::

### 4 つの分け方

1. 良品
2. 接着修理
3. 縫製修理
4. B 品

## B 品は早く現金化
:::proposal
問題: ルールがなく、倉庫に眠っていた
今後: 4 つに分けて、すぐ販売・修理。B-GRADE シートに記録
確認: 販売・修理までの日数／B 品の在庫数（月 1 回）
:::

### B 品の扱い
| 状態 | 扱い |
|---|---|
| 修理できる | 修理 → 再 QC → 良品で販売 |
| 小さな傷・汚れ・クラック | 15% OFF（それ以上は管理者に確認） |
| 部品の欠損 | 最大 50% OFF |
| 販売できない | 理由を記録して処分 |
