# 経理
> 売上・決済・返金を「毎日」確認し、未処理（ペンディング）を残さないことが基本です。毎日の確認がそろっていれば、月次レポートは集計するだけで終わります。

## 毎日のレジデータ・決済情報を確認し、売上を照合する

:::proposal
従来: レジデータ（POS）と決済情報（カード・QR・現金）の照合を都度は行わず、あとからまとめて確認していた。
問題: 確認が後回しになり、未照合・差額未解決のペンディングが発生。日数が経つと原因（打ち間違い・決済の二重処理・返金）を遡れない。
今後: 毎営業日の午前に前日分を照合し、日次チェック表に記入する。差額はその日のうちに店舗・担当へ確認し、理由と対応を記録する。
確認: 日次チェック表が毎日埋まっているか。未解決の差額が翌日に残っていないこと。
:::

### 今後の手順（毎営業日・午前）

1. 前日の POS 売上を店舗別・決済手段別（現金／カード／QR／振込）に出し、金額・件数を突き合わせる。
2. 差額があれば、当日中に店舗または担当へ確認し、理由（打ち間違い・二重処理・返金・未入金）を特定する。
3. 当日中に解決しないものは「ペンディング欄」に理由と期限を書く。

| 日付 | 店舗 | POS 売上 | 決済合計 | 差額 | 返金 | 対応・備考 | 確認者 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  | 有 / 無 |  |  |

## お客様への返金が発生していないか毎日確認する

:::proposal
従来: 返金（キャンセル・返品・決済エラー）の発生を都度は確認せず、店舗やお客様からの連絡で気づいていた。
問題: 返金処理が遅れてお客様を待たせる。返金分が売上照合と合わず、差額の原因になる。
今後: 毎日、POS の返品・返金記録、オンライン各チャネルの返金リクエスト、店舗からの報告の 3 つを確認し、チェック表の「返金」欄に記入する。発生していれば当日中に処理する。
確認: 返金の発生日と処理日の差（当日中を目標）。チェック表の返金欄が毎日記入されていること。
:::

### 今後の手順（毎営業日・売上照合と同時）

1. POS の前日分の返品・返金記録を確認する。
2. オンラインの注文管理画面（Shopee・Lazada・LINE・Web など）で返金リクエスト・キャンセルを確認する。
3. 店舗の日次報告・グループの連絡に返金の記載がないか確認する。
4. 返金があれば、金額・理由・決済手段を記録し、〔要確認〕承認者の確認のうえ当日中に処理する（現金／決済会社経由／振込）。
5. 日次チェック表の「返金」欄に「有」と金額を書き、売上照合の差額と突き合わせる。

:::kv
担当・頻度: 経理担当。毎営業日。
承認: 〔要確認〕返金の承認者と、承認が必要な金額の基準。
:::

## 月次レポートを作成する

:::proposal
従来: 〔要確認〕月次レポートの現在の作り方（誰が・何を・いつまでに）。
問題: 〔要確認〕日次の照合が終わっていないと、月末にまとめて数字を集める作業が発生し、完成が遅れる。
今後: 日次チェック表をもとに、月初の決まった日までに固定の様式でレポートを作る。内容は店舗別・チャネル別の売上、決済手段別の内訳、返金、差額とその理由、未解決のペンディング。
確認: レポートの完成日（月初から〇営業日以内）。前月の未解決ペンディングがゼロであること。
:::

### 今後の手順（月初）

1. 日次チェック表の 1 か月分がすべて埋まっていることを確認する（空欄があればその日を先に照合する）。
2. 店舗別・チャネル別（店舗／オンライン／イベント）の売上を集計する。
3. 決済手段別の内訳と、決済会社からの入金額を照合する。
4. 返金の合計と件数、差額とその理由をまとめる。
5. 固定の様式（前月と同じ項目・同じ順番）に入力し、〔要確認〕提出先へ期限までに提出する。

:::kv
担当・頻度: 経理担当。月 1 回、〔要確認〕月初〇営業日以内。
レポートの項目: 〔要確認〕上記以外に必要な項目（経費、在庫金額、イベント精算など）。
:::

# 店舗・イベント・オンライン物流
> 店舗・オンライン・イベントへ商品を動かす仕事は、オフィスが「週のリズム」と「締め切り時刻」で主導します。店舗スタッフ（PC）は販売に集中し、オフィスが在庫と補充を管理します。

## 店舗の在庫はオフィス側で管理し、毎週月曜日に補充する

:::proposal
従来: 店舗スタッフ（PC）が都度在庫を確認し、オフィスに依頼して発送していた。
問題: 店舗が確認・依頼に時間を取られて販売に注力できず、機会損失が生まれていた。オフィスも都度対応になり、効率が悪かった。
今後: オフィスが各店舗の在庫状況と販売状況を管理し、毎週月曜日に必要な補充商品を準備する。デリバリーノートを確認したうえで発送し、店舗は受領時にデリバリーノートと照合する。月末は PC の在庫報告でシステム上の在庫と照合し、オフィス・店舗ともにリアルタイムで正確な在庫を把握できる状態を保つ。
確認: 毎週月曜日に全店舗分の補充が発送されていること。月末照合の差異件数（店舗別・月別に記録）。店舗からの在庫依頼の件数（ゼロが目標）。
:::

### 今後の手順（毎週月曜日）

:::flow
- 月曜 午前: オフィスが在庫ダッシュボードと先週の販売状況を見て、店舗別の補充リスト（SKU × 数量）を作る
- 月曜 午前: 補充商品をピッキングし、デリバリーノート（店舗名・日付・SKU・数量）を作る
- 月曜 午後: 別の 1 名がデリバリーノートと箱の中身を照合してから発送する
- 店舗 受領時: PC がデリバリーノートと中身を照合し、相違があればその日のうちにグループで報告する
- オフィス: 発送分を在庫データに反映する
:::

1. 補充の判断基準は〔要確認〕（例：サイズ欠けの補充、在庫月数が〇か月未満の SKU、イベント・セール前の増量）。
2. デリバリーノートは必ず 2 名で確認する（作った人と発送する人を分ける）。
3. 店舗からオフィスへ戻す商品（返品・店舗間移動）も、発送した当日に内容をグループで報告する。

### 月末の在庫照合

1. PC は毎月末、店舗の在庫を数えて所定の様式で報告する（モデル × カラー × サイズ）。
2. オフィスはシステム上の在庫と照合し、差異のある SKU を一覧にする。
3. 差異の理由（販売未登録・補充の反映漏れ・返品未報告・紛失）を店舗と確認し、在庫データを修正する。
4. 差異件数と理由を月別に記録し、繰り返す理由があれば手順を直す。

### Paradise Park からのオンライン向け発送（週末）

1. 週末に Paradise Park からオンライン注文向けに発送した商品は、PC がリスト（注文番号・SKU・数量）にする。
2. PC はその日の売上報告と一緒にリストを報告する。
3. オフィスは翌営業日にリストをもとに店舗在庫を減らし、オンライン注文の発送済みを確認する。

:::kv
担当・頻度: オフィス（在庫担当・発送担当）：毎週月曜日。PC：受領時の照合、月末の在庫報告、週末のオンライン発送リスト。
デリバリーノートの様式: 〔要確認〕現在使っているものがあればそれを固定、なければ付録の様式を使う。
:::

## オンライン注文は当日 14:00 を締め切りに、締め切りまでの注文を当日発送する

:::proposal
従来: 朝一で注文を梱包して発送したあと、午前中に入った注文は翌日まで発送されていなかった。
問題: 当日発送できるはずの注文が翌日になり、お客様を待たせていた。配送日数の問い合わせも増える。
今後: 当日発送の締め切りを 14:00（2 PM）とし、締め切りまでに入った注文は必ず当日発送する。締め切り時刻は厳守し、例外を作らない。
確認: 14:00 までの注文のうち当日発送できた割合（毎日の出荷リストで確認、100% が目標）。
:::

### 今後の手順（毎日）

:::flow
- 9:00: 前日夜〜朝までの注文を出荷リストにし、ピッキング・梱包する
- 13:30: 午前中に入った注文を確認して出荷リストに追加し、梱包する
- 14:00: 当日分の梱包を締め切り、〔要確認〕集荷または持ち込みで配送業者に渡す
- 発送後: 各チャネルに追跡番号を入力し、出荷リストに「発送済み」を記入する
- 14:00 以降の注文: 翌日 9:00 の分として扱う
:::

1. 出荷リストには注文番号・チャネル・SKU・数量・発送時刻・追跡番号を書く。
2. 店舗在庫（Paradise Park など）から発送する注文は、発送した店舗がその日のうちに報告する（前項）。
3. 在庫がなく当日発送できない注文は、14:00 までにお客様へ発送予定日を連絡する。

:::kv
担当・頻度: オンライン担当。毎日 9:00 と 13:30 の 2 回。
配送業者の集荷時刻: 〔要確認〕
:::

## イベントの備品・什器はチェックリストで準備し、探す時間をなくす

:::proposal
従来: オフィスでの準備でも、ブースでの設営でも、備品や什器を探したり、足りているか確認したりするのに時間がかかっていた。
問題: 準備・設営の所要時間が読めず、抜け漏れがあると会場で買いに走る・取りに戻ることになっていた。
今後: オフィスの棚は整頓済み（備品ごとに定位置とラベル）。イベントごとに「備品・什器チェックリスト」を参照して準備し、積み込み前と撤収時にもチェックして抜け漏れを防ぐ。
確認: チェックリストが「準備時・積み込み時・撤収時」の 3 回記入されていること。会場で不足した備品の件数（ゼロが目標）。
:::

:::check 備品・什器チェックリスト（案・イベントごとに印刷）
- 什器：ラック／テーブル／椅子／試し履き用ベンチ／ミラー／サイズ計測器
- レジ：タブレット・POS／カードリーダー／レシートプリンター・ロール紙／釣銭／QR 決済の掲示
- 販促：サイン・バナー／価格表／POP／チラシ・名刺／SNS・LINE の QR
- 梱包：ショッパー（袋）／箱／テープ／ハサミ・カッター
- 電源・通信：延長コード／電源タップ／充電器・モバイルバッテリー／Wi‑Fi ルーター
- 消耗品：文具／清掃用品／ゴミ袋／救急セット
- 商品：持ち出しリスト（SKU × 数量）と箱数の一致
:::

1. 準備日：チェックリストを印刷し、棚の定位置から取り出しながらチェックする。
2. 積み込み時：もう一度チェックし、車両に積んだ箱数を記入する。
3. 撤収時：同じリストで持ち帰りをチェックし、紛失・破損を記録する。
4. 戻ったら備品を定位置に戻し、消耗品の補充が必要なものを備品担当に伝える。

:::kv
担当・頻度: イベント担当。イベントごと（準備日・積み込み時・撤収時）。
チェックリストの項目: 〔要確認〕上の案を実際の備品に合わせて直す。
:::

## 車両は事前に手配し、確保できたらグループで報告する

:::proposal
従来: 搬入・搬出の直前に配車していた。
問題: 車両が決まるまで待つ無駄な時間が発生し、積み込み・搬入の開始が遅れていた。
今後: イベントの日程が確定した時点で搬入・搬出の日時を決め、〔要確認〕〇日前までに車両を手配する。確保できたら、日時・車種・運転者をグループで報告する。
確認: 車両の確保報告がイベントの〇日前までにグループに出ていること。
:::

### 今後の手順

1. イベント確定時に、搬入日時・搬出日時・荷物の量（箱数・什器）を決める。
2. 荷物の量に合う車両を〔要確認〕〇日前までに手配する（自社車両／レンタル／配送業者）。
3. 確保できたら、グループに「日付・時間・車種・運転者・集合場所」を報告する。
4. 前日に、車両と運転者に再確認の連絡を入れる。

## イベント準備の全体フロー

:::flow
- イベント確定: 日程・会場・ブース規模を共有。車両手配と持ち出し商品の検討を開始
- 2 週間前: 持ち出し商品リスト（SKU × 数量）を確定。備品・什器チェックリストを印刷
- 1 週間前: 商品のピッキング・QC・梱包（所要時間は第 3 章の基準で見積もる）。車両確保を報告
- 前日: 積み込み。チェックリストで備品・商品の箱数を確認
- 当日: 設営 → 販売。日次で売上と残在庫を報告
- 撤収: 残在庫を数え、備品チェックリストで持ち帰りを確認
- 1 週間以内: 売上精算、残在庫をオフィス在庫へ戻す
:::

〔要確認〕イベント準備の資料（添付予定）をいただき次第、この流れを実際の手順と担当に合わせて書き直します。

# QC・検品
> 作業時間を測って「基準」にすれば、準備にかかる時間と人数が読めるようになります。基準は実績で見直します。

## 作業時間の基準（リードタイム）で準備を計画する

:::proposal
従来: QC・修理・梱包の作業が特定のスタッフに属人化しており、どのくらい時間がかかるか読めなかった。
問題: イベントや出荷の準備が予定どおりに終わらず、直前に人手を集めることになっていた。
今後: 実測した作業時間を基準にリードタイムを想定し、足数 × 基準時間で所要時間と必要人数を出してから準備を始める。実績を記録して基準を見直す。
確認: 準備の計画時間と実績時間の差。基準表が半年に 1 回見直されていること。
:::

| 作業 | 内容 | 基準時間 |
|---|---|---|
| シューズ初期 QC | 品質検査 | 1 分 40 秒／足 |
| シューズ修理（接着） | 糊付け修理 | 1 分／足 |
| シューズ修理（縫製） | 外部の修理職人へ委託 | 委託（納期は〔要確認〕） |
| イベント向け梱包 | ピッキング・箱詰め | 約 32.5 秒／足、約 6 分 4 秒／箱、約 111 足／時 |

イベント向け梱包の基準は、実測（347 足・31 箱を 3 時間 7 分 52 秒）から算出したものです。

### 所要時間の出し方（例：300 足のイベント）

| 作業 | 計算 | 1 人の場合 | 2 人の場合 |
|---|---|---|---|
| 初期 QC | 300 足 × 100 秒 | 約 8 時間 20 分 | 約 4 時間 10 分 |
| 梱包 | 300 足 ÷ 111 足／時 | 約 2 時間 40 分 | 約 1 時間 20 分 |

1. 準備する足数を確定する。
2. 上の基準で作業ごとの所要時間を出し、人数と日程を決める。
3. 作業の開始・終了時刻を記録する。
4. 実績が基準と大きく違ったら、理由（商品の種類・作業環境）を書いて基準を見直す。

## 初期 QC の手順

:::proposal
従来: 〔要確認〕検査する項目と不良の判断が人によって違っていた。
問題: 〔要確認〕店舗やお客様のもとで不良が見つかる。
今後: 検査項目を固定し、1 足 1 分 40 秒を目安に全足を検査する。結果は良品／修理（接着）／修理（縫製）／B 品に分けて、次の項目の仕分けへ進める。
確認: 検査後に店舗・お客様から戻った不良の件数（月あたり）。
:::

:::check 初期 QC チェック項目（案）
- 左右がそろい、サイズ表記が一致している
- ソールの接着に浮き・剥がれがない
- 縫い目のほつれ・糸の飛び出しがない
- アッパーに汚れ・傷・色ムラがない
- 箱・ラベルのモデル・カラー・サイズが中身と一致している
:::

〔要確認〕実際の検査項目と、良品／修理／B 品の判断基準。

## B 品の仕分けと早期の現金化

:::proposal
従来: 〔要確認〕B 品（ダメージ品）の扱いが決まっておらず、修理できるものも含めて倉庫に残っていた。
問題: 売れる商品が倉庫に眠り、現金化が遅れる。修理可能品と不可品が混ざり、判断に時間がかかる。
今後: QC の結果で仕分ける。修理不可の軽微なダメージ品は基本 15% 割引でクリアランス販売。修理可能品は接着（社内）・縫製（外部委託）に分けて修理に出し、再 QC のうえ良品として販売する。早期の現金化を優先する。
確認: B 品の仕分けから販売・修理に出るまでの日数。倉庫に残っている B 品の足数（月 1 回数える）。
:::

:::flow
- QC: 不良・ダメージを発見
- 仕分け: 修理可能か、修理不可の軽微なダメージか、販売不可かを判定
- 修理可能: 接着は社内で修理（1 分／足）、縫製は外部の修理職人へ委託 → 再 QC → 良品へ
- 軽微なダメージ（修理不可）: 基本 15% 割引でクリアランス販売
- 販売不可: 理由を記録して処分
:::

| 判定 | 基準 | 処理 |
|---|---|---|
| 修理可能 | 接着の浮き・軽いほつれなど、直せば良品になる | 接着は社内、縫製は外部へ。再 QC 後に良品へ |
| 軽微なダメージ（修理不可） | 使用に支障のない小さな傷・汚れ | 15% 割引でクリアランス（〔要確認〕販売場所、15% を超える割引の承認者） |
| 販売不可 | 大きな破損・安全性に問題 | 処分。品番・数量・理由を記録 |

:::kv
担当・頻度: QC 担当。QC のたび。倉庫の B 品は月 1 回数える。
:::
